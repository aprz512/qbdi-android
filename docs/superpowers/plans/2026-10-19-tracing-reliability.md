# 跟踪可靠性与验收改进

目标：按用户提供的 P0、P1、P2 顺序改进跟踪可靠性。保留已有配置与生命周期边界，不改动其他项目。

1. P0 并发入口：在 `tracer_entry_proxy_test` 建立两个线程重叠进入的失败回归。普通模式持久保留 hook，QBDI 执行保留的原始指令跳板；逻辑入口规则在跳板执行前运行，明确记录跳板的采集边界。验证并发、配置替换、卸载、fork 和停止路径。
2. P0 默认只读：默认规则集为空。自定义规则必须通过构建参数显式选择，并绑定样本；验证旧固定偏移不会修改寄存器，以及错误样本不会启用修改规则。
3. P1 启动链：专用适配器通过正式 `FridaInjector`、agent 和状态验证启动。适配代码只提供解包识别与策略，不再实现第二套 Frida 生命周期。
4. P1 模块身份：为无 build ID 的 ELF 提供显式 SHA-256 校验，校验本地与设备副本。说明 ELF 原点、匿名区域原点与半开偏移范围，覆盖多段、重载、4 KB/16 KB 布局。
5. P1 自动验收：联合 PID、`/proc/PID/stat` 启动时间、标题标志与持续时间，保存截图、规则命中、严格轨迹转换结果；提交精简验收摘要，原始样本和大文件继续留在忽略目录。
6. P2 缓冲测量：使用相同短函数比较缓冲大小、RSS 与调用耗时；有测量依据后调整默认值。

验证：先运行针对回归的失败测试，再修改并运行相关 host C++/Python 测试；构建 arm64 tracer，在明确绑定的设备上验证双线程和 AppGuard QBDI 退出线程策略。设备未执行的验收不得以 host 测试代替。最终摘要区分通过、失败和未验证，并记录命令、工作树状态及测量限制。


执行结果：P0/P1 已完成；主机 47 项 C++、875 项 Python（9 项跳过）通过，最终配置复查后相关 228 项再次通过，图像匹配 3 项单独通过。ARM64 双线程与入口回跳回归、最终游戏标题验收及样本哈希验证通过。P2 已完成两组缓冲测量；RSS 无明显改善，调用时间排序在两组间变化，保留现有通用默认值。精简凭据及限制见 `docs/benchmarks/qtrace-tracing-reliability-2026-10-19.{md,json}`。
