# 时间线页面请求与缓存诊断

日期：2026-10-19。基于 `72548df` 的工作区，范围为 UI-06。

## 页面所有权与边界

`TimelinePages` 按 workspace、projection 和前端 generation 隔离页面。滚动、双向翻页、事件跳转和历史恢复共用页面读取与定位请求；相同 cursor 的未完成查询只派发一次。每次导航在定位、取页和返回视图时检查所有权，被替代或取消的导航不能提交旧页面或旧错误。

缓存仍同时限制 128 页与 32 MiB 计量权重，每页至多 2,000 行；E2E 模式保持四页。游标位置随缓存页面保留，不再为远端跳转扩展稀疏数组。LRU 淘汰后可重新定位和读取。权重按 UTF-16 字符串长度与对象预留空间计算，每次新响应只计量一次，不建立整页 JSON 或 UTF-8 副本；计量权重不等于浏览器实际 heap。

底层 IPC 已派发后不能撤销；同一 projection 仍有效时，已取消消费者的响应可以填入有界缓存，供后续请求复用。关闭或切换 generation 会清空缓存，并阻止旧响应重新填入。搜索结果面板继续独立保存页面与 hit，不随时间线滚动翻页。

## 五轮本机方法

使用同一机器、Chromium、依赖和合成语料。优化前使用 `72548df` 的 App 与 SegmentCache；优化后使用证据文件记录的源码哈希。测量时停止其他浏览器验收，每个版本运行五个独立 Chromium 页面。

每轮挂载实际 App，API 返回 100,000 个合成指令事件，每页 2,000 行，每次取页固定等待 60 ms。依次浏览第 1–24 个非首页面，再回访末尾的四个页面；每次浏览在相邻 animation frame 提交三个相邻视口。连同初始首页面，共涉及 25 个唯一页面。每次核对实际渲染的目标事件，并记录时间线 DOM 行数。

记录页面查询次数、整页 JSON 序列化次数与累计耗时、视口请求到目标行可见的 p95、frame interval p95。挂载并取得首页面后和浏览结束后各强制 GC，读取整个诊断页面的 heap 增量；它包含 React、结果面板和诊断开销。

复现命令：

```bash
node qtrace-ui/tools/timeline_pages.mjs /tmp/qtrace-timeline-pages.json
```

固定 60 ms 响应延迟用于制造重叠请求。这项诊断不测量 Rust 查询或设备采集速度，视口延迟也不是 JavaScript 执行耗时。

## 本机结果

Chromium 153.0.8010.12。下表为前后各五轮的中位数；原始样本、源码哈希、依赖与主机身份见 [UI-06 证据](qtrace-timeline-pages-2026-10-19.json)。与其他验收并发运行的探索样本未计入本表。

| 指标 | 优化前 | 优化后 |
| --- | ---: | ---: |
| 页面查询次数 | 72 | 25 |
| 整页 JSON 序列化次数 | 53 | 0 |
| 整页序列化累计耗时 | 130.7 ms | 0 ms |
| 目标视口加载 p95 | 185.5 ms | 124.1 ms |
| frame interval p95 | 16.8 ms | 16.8 ms |
| 浏览后的 heap 增量 | 19,448,228 B | 14,162,728 B |

查询次数减少 **65.28%**，目标视口加载 p95 的中位数减少 **33.10%**，heap 增量减少 **27.18%**。各轮都完成相同的 29 次视口核对，时间线 DOM 最大均为 22 行。帧时间基本不变，不声称绘制速度提高。

Heap 变化同时受到请求合并与更保守的页面计量方式影响；相同的 32 MiB 计量上限可能更早淘汰页面。这里测量的是整个诊断页面，不能把全部下降归因于某一个内部对象。JSON 计时包含相同插桩的开销。

## 正确性与验收范围

改动前的 56 项前端测试通过；改动后新增 13 项回归，69 项全部通过。覆盖相邻视口的共享查询、重复定位、单消费者取消、被替代定位提前结束、迟到成功与失败、关闭和 generation 隔离、LRU 淘汰重取、跨页范围、双向翻页、直接定位 40 亿附近的偏移、过大页面不缓存，以及 cursor cycle。一个实际 App 回归在隔离目录使用原始实现时失败，明确记录期望两次查询却发生三次；当前实现通过。

最终版本通过 15 项工作区/持久化 E2E、1 项生产构建桥接隔离、TypeScript/生产构建及 ESLint。现有的可选大规模 E2E 未配置语料，保持跳过。最初 ESLint 与 Playwright 清理测试目录并发时出现过 ENOENT；顺序重跑通过，未修改 lint 规则。

四份保留的小米产物均通过 Chromium 与真实 Rust 服务回归：offset/symbol 各 987 个事件、monitor-exit 为 1,714 个事件，Flight 为 1,185,909 个事件。覆盖上下文、准确事件总数、筛选、寄存器、调用树与事件跳转、内存和历史、空结果、标注/高亮及服务重启后的恢复；Flight 另覆盖结果双向翻页与远端末页导航。没有接口错误或页面错误。脚本、产物身份、截图路径和各项结果均记录在证据文件中。

这项本机合成性能对比与保留产物功能验收不替代固定主机规模门禁、Tauri WebKit、高缩放布局或新的 Android 性能验收。Rust 服务、协议和参考性能报告未修改；UI-08 布局与可访问性检查仍待实施。
